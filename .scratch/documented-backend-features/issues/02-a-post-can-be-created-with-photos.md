# 02: A post can be created with photos

**What to build:** A user creates a post with up to 10 photos, with or without text, and everyone who can read the post gets the photos' addresses and can fetch them. Today a post is text only and nothing in WebCity accepts a file.

This is the first upload, so it also builds the one storage class that owns all file handling (checking, saving, deleting, turning a stored file into its address). Later tickets reuse it for removing photos and for message photos, and it is the single place to change if images move to cloud storage after the deadline.

Creating a post changes from a JSON body to `multipart/form-data`. A post needs a title, and either text or at least one photo.

Full decisions are under "Images" in `.scratch/documented-backend-features/spec.md`. The ones that are easy to get wrong:

- The format is decided by the file's leading bytes, not its name or declared type. Accepted: JPEG, PNG, WebP.
- File names are generated by the server. The client's file name never appears in a path.
- If any file fails a check, the whole request is refused: no post, no stored file.
- Photos are served as static files from a path under `/api`, and the address stored and returned is relative, so only `/api` and `/hubs` cross the proxy (ADR 0001).
- The limits and the upload folder come from configuration with defaults in the options class, because the settings files are gitignored.
- The server's default request size is smaller than ten 5 MB photos, so the limit on this endpoint is raised to fit.

Out of scope: removing a photo and cleaning up files when a post is deleted (ticket 04), adding photos to an existing post, resizing or thumbnails.
